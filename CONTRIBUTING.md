# Contributing

Thank you for your interest in Personal Intelligence System Suite.

## Current contribution policy

The project is dual-licensed: repository code is available under `AGPL-3.0-only`, and the project may also offer separate commercial licenses for code for which the copyright holder has sufficient rights.

Because a dual-license model depends on clear contribution rights, substantive third-party code contributions are **not automatically accepted** merely because the repository is publicly available.

Until a Contributor License Agreement (CLA), copyright assignment, or another reviewed contributor-rights mechanism is adopted:

- issues, bug reports, feature proposals, documentation feedback, test cases, and design discussions are welcome;
- small corrections may be reviewed case by case;
- substantial third-party code should not be merged without an explicit review of ownership, provenance, and licensing rights;
- contributors must not submit code, data, assets, model weights, or other material they do not have the right to contribute;
- copied code must retain required notices and must be compatible with the project's licensing strategy.

## Developer Certificate / sign-off

No DCO or CLA is currently declared as sufficient by itself to grant commercial relicensing rights. Do not interpret a Git sign-off as a commercial relicensing grant unless a separate contributor agreement explicitly says so.

## Third-party material

Contributions that add dependencies, external binaries, models, datasets, fonts, or other third-party materials must identify their source and license. Unknown or non-commercial licenses must be treated as a licensing review blocker until resolved.

## AI-assisted contributions

Contributors remain responsible for the provenance and licensing of AI-assisted code or content they submit. Do not submit generated material if its provenance or right to contribute it is uncertain.

## Security and private data

Never commit private documents, credentials, API keys, model secrets, production databases, personal data, or private corpus extracts.

## Future CLA

A formal CLA may be introduced before accepting substantial external code contributions. Any CLA must be reviewed separately; this file is not a substitute for that agreement.
